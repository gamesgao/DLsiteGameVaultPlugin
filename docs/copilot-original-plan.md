# GameVault 原生 DLsite Metadata Provider 开发与验收计划

**建议采用独立 TypeScript 插件：在 GameVault 后端进程内注册原生 MetadataProvider，将 DLsite 抓取与规范化逻辑独立为纯 Node.js 模块。** 自动匹配以明确作品 ID 为唯一默认依据；无 ID 的游戏通过原生搜索与人工 remap 完成关联。服务器负责持久化元数据和封面、背景图，客户端读取同一份服务器数据。

本计划基于指定本地源码的只读检查。**本次未修改文件、安装依赖、运行测试、启动服务、联网或连接 NAS；以下均为后续实施与验收要求，不是已实现或已通过的结果。** 计划正文由调用方落盘。

---

## 一、交付范围与非目标

### 1. 首发必须完整交付

首发不是“能抓取一个商品页”的演示，而是以下闭环：

1. 插件在指定 GameVault 后端版本中加载、注册，并出现在 metadata provider 列表。
2. 从游戏文件名中的明确 DLsite ID 自动关联作品；支持直接输入 ID、商品 URL 搜索并人工 remap。
3. 无 ID 时支持标题搜索、候选去重、候选信息展示，不自动采用搜索第一条。
4. 实现常用字段、图片入库、来源链接，以及无法原生对应字段的明确降级。
5. 接入现有保存、优先级合并、TTL、手动刷新、remap/unmap 流程。
6. 网络故障、下架、限流、页面结构变化和图片失败不能清空已有有效数据。
7. 提供可重复构建的 ESM 发行包、安装升级卸载文档、兼容清单和完整验收记录。

### 2. 明确不做

- 不做 Playnite 双向同步，也不扩展官方 Playnite 桥接。
- 不用外部脚本直接回写 GameVault 数据库。
- 不依赖 Playnite、.NET、浏览器自动化或新增常驻服务。
- 不维护 GameVault 核心 fork，不顺带修复 VNDB 插件。
- 不改游戏包内容，不自动重命名文件，不下载游戏本体、试用包或购买内容。
- 不抓取需要用户登录、购买权限或绕过访问限制的页面。
- 不承诺 DLsite 所有历史分区、停用接口和全部客户端界面的未经验证行为。
- 本阶段不进行 NAS 探测或部署。未来实际部署仍须单独授权。

## 二、源码核验结论与接入约束

以下路径以 `/tmp/gamevault-research` 为简称；本次实际读取的是其 macOS 对应路径 `/private/tmp/gamevault-research`。

| 已核验代码/文档 | 对实现的直接约束 |
|---|---|
| `backend/src/plugin.ts`、`src/main.ts` | 插件通过扫描 `*.plugin.module.js` 动态导入，再加入 Nest 根模块；入口必须默认导出模块类。生产模式会把 `/plugins` 内容复制进 `dist/src/modules`。 |
| `backend/package.json`、`tsconfig.json`、`tsconfig.build.json` | 当前基线为 **17.0.1、ESM、NodeNext**；编译包含 `.local/plugins/**/*`。必须保留装饰器元数据及明确的 `.js` 相对导入。 |
| `docs/docs/server-docs/plugins.md` | 官方路径是把插件放入 `.local/plugins`，随后端共同编译；不得携带第二套 NestJS 或 `reflect-metadata`。 |
| `backend/src/modules/metadata/providers/abstract.metadata-provider.service.ts` | 实现 `search()`、`getByProviderDataIdOrFail()`，覆写 `getBestMatch()`。不调用默认“相似度排序取首条”的自动匹配逻辑。 |
| `backend/src/modules/metadata/metadata.module.ts` | 导出 metadata 及四类关联实体服务；插件应复用这些服务，不能重新提供另一套实例。媒体另导入 `MediaModule`。 |
| `backend/src/modules/metadata/metadata.service.ts` | 框架提供按游戏排队、provider TTL、map/unmap、优先级合并。但 `request_interval_ms` 只是一次 provider 更新前等待，不是所有 HTTP 请求的统一限速。 |
| `backend/src/modules/metadata/games/game.metadata.entity.ts` | 游戏元数据唯一键为 `(provider_slug, provider_data_id)`；封面和背景必须是 `Media`；描述声明支持 Markdown。 |
| `backend/src/modules/metadata/games/game.metadata.service.ts` | 保存时四类关联数组先初始化为空。**只返回稀疏对象可能清空开发者、发行商、标签、类型关联。** |
| `backend/src/modules/metadata/metadata.service.ts` | 合并时高优先级覆盖低优先级的非空字段；关联数组按字段整体覆盖，不是跨 provider 自动求并集。`user_metadata` 最后覆盖。 |
| `backend/src/modules/media/media.service.ts` | `downloadByUrl()` 使用普通 `fetch`，没有完整的来源白名单、逐跳检查和 DNS 内网防护，不能直接接收页面提供的任意 URL。 |
| `backend/src/modules/media/media.controller.ts` | 媒体按不可变 ID 设置长期缓存。图片更新应创建新 Media，不能原地替换旧文件内容。 |
| `backend/src/modules/games/files.service.ts` | `extractTitle()` 删除所有圆括号内容，但保留方括号。ID 应优先放在 `[RJ…]`，不能放在 `(RJ…)`。 |
| `backend/src/modules/games/games.service.ts` | 索引会按文件路径、标题及年份归并版本。保留文件标题中的不同 ID，有助于避免不同作品被归入同一游戏。 |
| `backend/src/modules/metadata/metadata.service.ts` | 任一版本路径包含 `(NC)` 时，自动更新队列跳过该游戏的所有 provider。插件不能将其解释成“只禁止其他来源”。 |
| `backend/src/modules/metadata/metadata.controller.ts`、`games/games.controller.ts`、`games/games.service.ts` | 已有 provider 搜索接口及 `mapping_requests` 更新入口，优先复用，不另建一套 remap API/UI。 |
| `backend/vitest.config.ts` | 后端默认只收集 `src/**/*.spec.ts`，不会自动运行 `.local/plugins` 下测试；插件必须有明确的测试入口。 |
| `playnite-dlsite/source/*`、`LICENSE` | 可以移植选择器、字段词典、日期规则和请求协议；保留 MIT 许可及 `Copyright (c) 2025 Mysterken`。不能照搬宽泛异常吞掉、日期解析失败默认值等行为。 |

### 必须先验证、不能直接承诺的宿主边界

**第一阶段先做契约验证，再继续完整实现：**

- `MetadataService.map()` 当前按“抓取 → 保存 provider metadata → unmap → 重新关联”执行，不是显式事务。远端失败发生在保存前，可以由插件阻止破坏；**数据库故障或并发 remap 的事务安全不能仅靠 provider 方法保证**。
- 媒体上传与 GameMetadata 建立引用存在时间窗口，需验证与 `media-garbage-collection.service.ts` 并发时的行为。
- `unmap` 没有持久的“禁止此 provider 以后自动匹配”标志；下一次索引可能再次匹配。
- 停用或卸载 provider 后，新的 merge 会跳过未注册来源；旧 effective metadata 是否仍显示，取决于何时重新合并，不能承诺“卸载立即全部恢复”。
- 插件加载器捕获导入异常后可能返回空插件列表。验收必须检查 provider 实际注册，不能只看服务器健康接口正常。

若这些边界导致必需验收无法通过，应记录最小复现和所需宿主扩展，优先等待上游受支持修复；**不通过 monkey-patch、直接改核心服务或永久关闭 GC 来掩盖问题。**

### 2. 分层责任

| 模块 | 责任 |
|---|---|
| `core/identity` | ID 提取、URL 解析、分区与别名规范化；不依赖 Nest、数据库或文件索引服务。 |
| `core/transport` | HTTPS、域名及 DNS 安全、限速、超时、重试、重定向、响应大小限制。 |
| `core/client` | 商品 HTML、补充 JSON、搜索请求，以及缓存和 single-flight。 |
| parser / normalize | 静态 DOM 解析、字段来源记录、语言回退、日期/评分转换、HTML 清理。 |
| provider service | 原生接口、自动匹配策略、配置、错误到 Nest 异常的转换。 |
| metadata mapper | 纯结构化数据到 `GameMetadata` / `MinimalGameMetadataDto` 的转换。 |
| snapshot reader | 只读取同一 DLsite 作品已有的 provider metadata，构造安全刷新快照。 |
| media adapter | 安全下载后的图片入库、已有图片复用、来源记录及失败清理。 |

### 3. 默认依赖与部署形态

默认使用 TypeScript、Cheerio 静态 DOM 解析、Turndown 转 Markdown，以及经过验证的 IP 地址分类库；网络使用 Node 的 HTTPS/DNS 能力，便于绑定已验证的 DNS 结果。版本在实施时按目标 Node 版本锁定。

- Cheerio 只使用静态解析能力，不加载页面资源、不执行脚本。
- 测试沿用 Vitest。
- 插件私有纯 JS 依赖随抓取核心打包，避免在 NAS 容器内运行包管理器。
- NestJS、TypeORM、`reflect-metadata` 和 GameVault 服务、实体全部使用宿主实例，不打包副本。
- 最小部署为：**现有 GameVault 后端 + 一个编译好的插件目录**，没有新增服务或数据库。
- 正常元数据与媒体的持久化使用现有数据库和媒体卷；不新增 GameVault schema。

## 四、作品身份、文件名和语言规则

### 1. 稳定身份

默认：

- `provider_slug = "dlsite"`
- `provider_data_id = 完整、规范大写的作品编号`
- `provider_data_url = 经过校验的规范商品 URL`

例如，同一作品的不同界面语言和合法分区跳转最终仍使用 `RJ150726`，不把语言、查询参数、版本或分区写入主键。

必须保留：

- `RJ`、`BJ`、`VJ`、历史 `RE` 前缀。
- 六位和八位数字形式。
- 数字前导零，不转为整数。
- 不同编号的翻译版、重制版、合集、续作及重新上架版之间的独立身份。

**不得仅凭相同数字尾部把 `RE` 改成 `RJ`，也不得把六位编号自行补零变成八位编号。**

### 2. 输入规则

| 输入 | 默认处理 |
|---|---|
| `[RJ150726] 游戏名`、`游戏名 [rj150726]` | 大小写规范化后提取；保留原文件标题，不改名。 |
| 纯 `RJ150726`、`BJ…`、`VJ…`、`RE…` | 按完整 ID 验证，不作为普通标题模糊搜索。 |
| DLsite 商品 URL | 用 URL 解析器读取 host/path/ID；不能使用“字符串包含 dlsite”判断。 |
| 同一个 ID 重复出现 | 去重后视为一个身份。 |
| 同一标题或多个版本出现不同 ID | 拒绝自动匹配并记录冲突，不猜测哪个版本代表整部作品。 |
| ID 嵌入更长字母数字串、长度不受支持、数字残缺 | 明确诊断为无效/暂不支持，不截取部分编号。 |
| URL 与文本中的 ID 不一致 | 拒绝自动匹配，交给人工 remap。 |

ID 提取顺序为：原始 `game.title`、已加载版本的文件 basename、旧 `file_path` 的 basename。**不读取游戏包内容，也不从父目录名随意推断 ID。**

必须先提取 ID，再清理用于标题搜索的文本。不得先删除所有方括号内容。

推荐文件名：

```text
游戏名 [RJ150726] (v1.0) (W_P) (2015).zip
```

### 3. 分区与旧 URL

首发搜索基线覆盖 Playnite 实现中的 `home`、`maniax`、`soft`、`pro`。商品 URL 另外核验原实现接受的 `aix`；移动版等 URL 仅在有明确规则和 fixture 后规范化到桌面商品路径。

实施时建立版本化路由表：

- RJ/RE：核验 `home` 与 `maniax` 商品定位及重定向。
- VJ：核验 `soft` 与 `pro`。
- BJ：补齐实际商品路径、页面结构与可用性证据，不能凭前缀臆造分区。
- 其他分区只有在明确列入兼容表并通过测试后才允许抓取。

裸 ID 的定位采用已核验的有限路由序列；只有明确“不存在/分区不匹配”才尝试下一条。403、429、超时不能触发遍历所有分区。

跨分区但作品 ID 不变可以归一化；**作品 ID 改变的跳转默认拒绝自动合并**。只有独立证据确认历史别名关系后，才能加入有测试的别名表。跳转到推荐页、登录页或首页不算成功。

BJ 等编号应支持识别、直接查询和明确的不可用诊断；若页面表明是漫画、音声等非游戏内容，不能因“ID 精确”就自动映射成游戏。人工明确选择可以关联其作品元数据，但不得修改 GameVault 的游戏包类型。

### 4. 语言

默认服务器统一使用 `ja_JP` 原文；配置可选择首发验证过的 `zh_CN`、`zh_TW`、`en_US`、`ko_KR`，缺失时回退 `ja_JP`。

- 界面语言不等于作品自身支持的语言。
- 不调用机器翻译服务。
- 语言进入抓取缓存键，但不进入 `provider_data_id`。
- 字段记录实际来源语言，日志说明发生了回退。
- 移植其余 Playnite 语言词典作为扩展基础，但未经日期、页面和字段验证的语言不宣称已正式支持。
- 更改服务器语言后刷新同一记录，不生成另一条作品 metadata。

## 五、全字段映射与降级策略

### 1. Playnite 15 类字段

| Playnite 字段 | GameVault 原生字段 | 首发规则及信息损失 |
|---|---|---|
| Name | `title` | 经验证的 JSON `work_name` 或 HTML `#work_name`；不把界面遮罩、模板占位符当标题。不改文件名和 `GamevaultGame.title`。 |
| Description | `description` | 提取作品说明区域，清理后转换为 Markdown；去除广告、购买区、脚本与跟踪内容。 |
| CoverImage | `cover: Media` | 使用页面声明的主图；校验来源和真实图片类型后入库。不猜测未出现的图片 URL。 |
| BackgroundImage | `background: Media` | 优先选择非主图的有效宽图，按固定规则选择；没有合适图片则缺省，不随机改变。 |
| Developers | `developers[]` | 同人页的社团默认作为制作团队；商业页依据明确品牌/制作字段。作者只有在制作角色明确时加入。 |
| Publishers | `publishers[]` | 只映射明确发行主体或明确自发行信息。不把销售平台 DLsite 硬编码为发行商，不无条件复制社团。 |
| Genres | `genres[]` | 默认放 RPG、ADV、ACT 等作品/游戏类型。使用稳定远端代码及规范名称。 |
| Tags | `tags[]` | DLsite 题材分类、已验证的其他标签；与 Genres 分工明确，不盲目复制两份。 |
| ReleaseDate | `release_date` | 按已知语言格式严格解析，保存日期语义；不得把解析失败写成公元 1 年、1970 年或抓取当天。 |
| CommunityScore | `rating` | 抓取层保留 `ratingStars`，确认是 0–5 星后只乘一次 20，生成 0–100 分；如 4.25 → 85。无评价、模板变量、非法数值不写成 0。 |
| AgeRating | `age_rating` | 明确全年龄 → 0，R15 → 15，R18 → 18；未知保持未知并记录诊断。不因前缀推断全年龄。 |
| Links | `provider_data_url`、`url_websites[]` | 保留规范商品页及通过校验的作品相关链接；原链接名称没有原生列，会损失。 |
| Series | `tags[]` | 使用 `Series: 名称`；优先用页面系列 ID 构造稳定标签身份。不是新增 Series 列。 |
| Features | `tags[]` | 使用 `Feature: 名称`。仅映射已核验的作品特性，不把所有页面图标都变成标签。 |
| Icon | 无独立字段 | 首发不映射；可以在内部解析结果保留来源，但不能用缩略图覆盖封面冒充 Icon 支持。 |

默认不把声优、配乐、画师、编剧全部混入 Developers。角色人员信息可留在内部结构，未来可增加明确标识的展示，不扩大首发原生字段承诺。

### 2. 其他原生字段与不对应信息

| 数据 | 处理 |
|---|---|
| 商品示例图片 | 可映射经校验的 `url_screenshots[]`；这些仍是外部 URL，不承诺离线可用。封面和背景必须本地入库。 |
| `url_trailers`、`url_gameplays` | 没有明确可靠来源时不填，不抓取任意 iframe。 |
| `notes` | 默认不写，避免挤占管理员公共说明。 |
| 价格、销量、文件容量、更新时间、人员 credits、作品语言 | 不冒充原生专列。仅在规范化数据/诊断缓存保留需要的信息；可选 notes 展示不属于默认行为。 |
| `average_playtime` | 无可靠来源，不填。 |
| `early_access` | 不从营销文案推断，遵从 GameVault 文件信息合并规则。 |
| 启动、安装、卸载命令及可执行文件字段 | 一律不从页面映射。 |
| 本地安装包大小、版本、游戏类型 | 由 GameVault 索引负责，不用商品页数据覆盖。 |

### 3. 关联实体身份

开发者、发行商、标签、类型均使用 `provider_slug="dlsite"`：

- 优先采用远端 `maker_id`、genre ID、work type code、series ID。
- 采用不同命名空间，例如 `maker:RG07939`、`genre:433`、`work-type:RPG`。
- 无远端 ID 时，使用“字段类别 + 规范化名称”的确定性哈希，不能用数组位置、随机数或单纯英文 slug。
- 名称为空的实体不得入库。
- 必须验证中日韩文字、标点差异和改语言后的去重行为；同时检查宿主生成 effective metadata 时的关联名称规范化是否造成碰撞。

### 4. HTML 和链接清理

保留标题、段落、列表、强调、必要链接和换行；移除脚本、表单、事件属性、样式、iframe、SVG、对象嵌入及跟踪像素。默认移除描述内嵌远程图片，以免客户端绕过媒体策略直接加载任意资源。

Turndown 本身不视为完整安全过滤器：应先按允许的 DOM/属性规则清理，再转换，并检查输出链接。

`url_websites` 等字段使用 `simple-array` 存储，还需验证 URL 中逗号的编码与往返行为，不能直接拼入会被拆分的字符串。

## 六、自动匹配、搜索与人工修正

### 1. 默认置信策略：ID-only 自动关联

首发自动匹配的采纳条件为：

**只有一个明确 ID → 定位成功 → 页面身份一致 → 确认可作为游戏来源 → 才允许自动关联。**

这就是默认置信边界，不引入未经校准的“相似度 80% 即可信”。

- ID 不存在、出现冲突或页面身份无法确认：拒配。
- ID 请求失败：报告失败，不退回标题搜索挑选另一部作品。
- 无 ID：`getBestMatch()` 返回明确的未匹配结果，通过 `NotFoundException` 接入框架已有分支。
- 不调用 `super.getBestMatch()`。
- 不覆盖已有映射：框架刷新已有 provider metadata 时应继续使用已保存 ID，不能重新根据标题抢回人工 remap。

**无 ID 自动模糊匹配不作为首发默认功能。** 这不影响完整交付，因为原生搜索与人工 remap 是无 ID 的正式工作流。

### 2. 搜索

`search(query)` 同时支持：

- 明确 ID、合法商品 URL：返回精确作品候选或明确错误。
- 普通标题：查询配置的分区，汇总、去重、排序并返回候选。

候选至少包含 `provider_slug`、`provider_data_id`、真实作品标题；有可靠来源时提供日期、封面 URL 和摘要。可以在摘要中补充 ID、社团、分区、作品类型等辨识信息，不能污染保存后的正式标题。

排序使用保留 CJK 的 Unicode 规范化、精确标题优先和确定性的标题相似度；数字、前后篇、续作、语言版本等差异不得清洗掉。分数仅用于候选排序，不能改变自动采纳规则。

默认每分区一页，最终候选不超过 30 条；查询正确 URL 编码，禁止把用户输入直接插入路径模板。无有效“零结果”页面证据时，不能把解析失败返回为 `[]`。

多个分区发生失败时，首发优先返回明确的“不完整搜索”错误，而不是把部分结果伪装成完整结果。

### 3. 原生人工工作流

复用：

- `GET /api/metadata/providers`
- `GET /api/metadata/providers/dlsite/search?query=…`
- `PUT /api/games/:game_id` 中的 `mapping_requests`

正常客户端通过现有 remap 界面完成选择；API 文档作为兼容验收和管理员故障诊断入口，而非外部脚本回写方案。

必须验证：

- 搜索后选择另一 ID，服务器实际改为目标作品。
- 同一 ID 重新 remap 可以请求刷新，不必先 unmap。
- unmap 不删除 `user_metadata`。
- **unmap 是解除当前关联，不是永久禁止自动重配。**
- `(NC)` 使自动更新整部游戏停止。当前源码的直接人工 map 入口没有相同队列检查，文档不得将 `(NC)` 宣称为不可绕过的访问控制，也不得把人工入口用作自动刮削绕行办法。

## 七、刷新、缺字段和失败时的数据保护

### 1. 解析结果显式区分状态

内部字段应区分：

- `present`：已验证的值。
- `absent`：页面结构有效，并能确认该字段确实没有内容。
- `unavailable`：请求失败、选择器失效、格式异常或访问限制导致无法获知。

不能用同一个 `null` 表达这三种情况。

### 2. 安全刷新顺序

1. 校验输入身份并读取**相同 `(dlsite, ID)`** 的已有 provider metadata，加载四类关联和媒体。
2. 完成 HTML、适用的 JSON 补充及图片处理，尚未确认的数据不进入保存阶段。
3. 校验标题、作品身份、字段类型、范围和来源。
4. 构造完整 provider 快照，尤其是四类关联数组。
5. 返回给宿主 `map()`，由现有服务保存、关联和合并。

不得读取或覆盖 `user_metadata` 作为 DLsite 的旧值，不得把另一个 ID 的旧映射拼入新作品数据。

### 3. 默认保护策略

- 整页网络失败、错误页面、标题/身份失效：抛错，原映射不变。
- 曾有值的字段变成 `unavailable`：默认拒绝本次刷新，保留原记录，避免将“不完整刷新”写成最新时间。
- 真实有效的字段缺省：不造值。
- 只有在完整结构和规则能确认列表变化时，才允许移除旧关联；选择器没找到不能等同空列表。
- 页面提供了需要下载的封面/背景，但下载失败：默认不发布本次新快照，避免抬高宿主 TTL 后长期失去重试机会。
- 下架或明确不存在：保留最后有效元数据和媒体，记录“来源不可用”；不自动 unmap 或删除作品。
- 评分缺失不写 0，年龄未知不写 0，日期失败不写默认日期。

首次导入本来没有某个可选字段可以缺省；但请求失败、结构错误或图片下载失败不能通过“空字段成功”掩盖。

### 4. 错误分类与日志

至少区分无效输入、作品不存在、非游戏自动拒配、身份冲突、搜索歧义、访问受限、限流、超时、解析结构变化、图片失败和宿主持久化失败。

日志包含 provider、作品 ID、阶段、错误码、重试次数和下次允许请求时间；默认不输出完整文件路径、页面正文、Cookie 或完整库标题列表。

旧快照用于保护已保存数据，**不能在联网刷新失败后原样返回旧值，让宿主把它标为刷新成功。**

## 八、安全 HTTP、媒体入库与统一请求预算

### 1. 来源校验

所有商品页、JSON、搜索、图片以及重定向共享同一个安全传输层。

默认要求：

- 只允许 HTTPS，禁止用户信息段、异常端口和未支持协议。
- 商品/搜索/JSON 只允许核验后的 DLsite 主机及路径模板。
- 图片初始白名单以样本确认的 `img.dlsite.jp` 为基础，只接受已验证图片路径；扩域必须有样本与测试。
- 不使用 `*.dlsite.*`、字符串 `contains` 或不带边界的后缀匹配。
- 每次重定向都重新校验主机、路径、协议和 DNS，最多三跳。
- 拒绝 loopback、私网、链路本地、保留地址、IPv4-mapped IPv6 等非公网地址。
- 将验证后的 DNS 地址绑定到实际连接，避免“先检查、后重新解析”的 DNS rebinding 窗口，同时保留正确 TLS 主机验证。
- 页面中出现的本地文件、内网、云 metadata 地址等不能产生网络请求。
- Ci-en 等外链只在准确核验的允许列表中保存，不为获取更多 metadata 自动访问。
- Cookie 仅限所需的匿名 locale/年龄确认行为，不能携带用户账号 Cookie，也不能跨主机转发。
- 不绕过 CAPTCHA、403、地区限制或登录限制。

### 2. 媒体接入

采用“插件安全下载 Buffer → 宿主媒体存储”的方式，不让宿主再次根据未受保护的 URL 发请求。

当前 `MediaService.upload(file, username)` 可以复用类型验证、原子文件写入和 Media 保存，但有两点必须在早期契约验证：

- 公共签名要求 `username: string`，内部创建媒体允许不设置 uploader。将当前源码的匿名分支调用封装在唯一适配点，验证 `upload(file, "")` 的实际行为；不伪造用户、不使用不安全类型断言。
- `upload()` 不设置 `source_url`，由适配层通过宿主 Media 实体记录已验证来源，或者明确记录于关联缓存；不能误以为它自动保留来源。

若目标宿主版本不支持该路径，应要求受支持的 Buffer 入库扩展，不能退回无防护的 `downloadByUrl()`。

进一步要求：

- 只允许首发测试过的 JPEG、PNG、WebP 等位图，验证文件签名，不信任扩展名或 Content-Type。
- 单图默认不超过 10 MiB，并遵从更小的宿主有效限制；限制图片尺寸/像素数，防止异常图片耗尽资源。
- 先完成远端下载验证，再尽量缩短上传到建立引用的窗口。
- 相同有效内容复用已有 Media；图片内容变化创建新 ID。
- 失败仅清理本次创建、确认尚未引用的临时资源，不删除旧图或其他游戏共享媒体。
- 原有媒体不可用时明确报告并重新获取，不返回悬空引用。

### 3. 默认限速与预算

以下是运行参数，不是开发工期估计。

| 项目 | 首发默认 |
|---|---|
| 全插件 HTTP 并发 | 1；搜索、HTML、JSON、图片和重试共同遵守 |
| 请求启动间隔 | 至少 1,500 ms，重定向也计入 |
| 单请求超时 | 15 秒 |
| 单次作品获取执行预算 | 最多 90 秒，不含排队等待 |
| 单作品 HTTP 总预算 | 最多 12 次，包含重定向、回退、图片和重试 |
| 重试 | 仅幂等临时故障；单逻辑请求最多额外 2 次，整个作品额外重试预算同样最多 2 次 |
| 搜索 | 每分区最多一页，最终最多 30 个候选 |
| HTML / JSON 上限 | 默认分别 5 MiB / 1 MiB，按解压后实际字节数限制 |
| 429 | 遵守 `Retry-After`，共享冷却；不在每个游戏任务中重复等待和重试 |
| 403 / CAPTCHA | 不立即重试，触发共享冷却并报告访问受限 |
| 持续网络/结构异常 | 熔断；后续任务快速报告暂不可用，避免整个库反复请求 |

插件的 `request_interval_ms` 默认设为 0，避免框架等待与插件限速重复计算；真实限速由唯一传输层承担。

### 4. 缓存及责任分界

| 能力 | 负责方 |
|---|---|
| 每游戏 metadata 更新任务、已有映射 TTL、有效 metadata 合并 | GameVault |
| 最后成功的 metadata、关联实体、封面和背景持久化 | GameVault 数据库及媒体卷 |
| 搜索缓存、HTTP 条件请求、同作品 single-flight | 插件 |
| 所有请求的限速、重试预算、熔断、负缓存、响应体限制 | 插件 |
| 图片来源安全、内容去重与复用判断 | 插件 |
| 持久化失败和并发 map 事务安全 | 必须验证的宿主边界，不能声称插件已包办 |

默认搜索缓存 10 分钟，明确不存在的负缓存 30 分钟；403/429 不得进入“作品不存在”缓存。

详情不增加另一层长 TTL：只允许短时、最多 30 秒的有效快照交接/并发合并，避免 `getBestMatch → getByProviderDataIdOrFail` 立即重复抓取。除此之外刷新应重新验证远端数据，可以使用 ETag/Last-Modified。

内存缓存使用有容量和字节数上限的 LRU，不缓存整座库的原始 HTML。若需要跨重启保留 `Retry-After`，仅在现有配置卷的插件专属小型状态文件中保存冷却信息，原子写入并校验格式，不新增服务。

**框架失败任务没有持久重试队列。** 短重试耗尽后，恢复依靠下一次索引或人工 remap；首发不另做一个扫描器。文档须说明 TTL 是“何时允许再更新”，不是每个作品独立运行的刷新定时器。

## 九、ESM 构建、发行、安装、升级与卸载

### 1. 构建路径

1. 锁定本地基线对应的后端 commit、`package.json`、lockfile，以及实际构建 Node 版本。
2. 在独立构建工作区准备该后端，不修改研究源码。
3. 将 `plugin/` 内容暂存到后端 `.local/plugins/dlsite/`。
4. 将纯抓取核心及插件私有依赖打包为 ESM，同时提供适配层编译需要的声明文件。
5. 使用后端 TypeScript/Nest 构建编译插件适配层，保留 decorator metadata。
6. 从 `dist/.local/plugins/dlsite/` 提取插件，并补入核心 bundle、运行所需静态资源与许可证。
7. 在干净的生产目录布局中加载发行包，验证复制到 `dist/src/modules/dlsite/` 后所有导入仍正确。

插件根目录采用与官方示例一致的宿主相对导入；嵌套文件的路径按实际深度处理。禁止保留 `src/...` 这种未经运行时解析支持的别名。

### 2. 发行产物

发行包至少包含：

- `dlsite.plugin.module.js` 及必要适配层 JS。
- 抓取核心 ESM bundle。
- 明确 `"type": "module"` 的包边界。
- 插件版本、兼容后端版本/commit、构建 Node 版本的清单。
- 校验和、安装说明、LICENSE、第三方许可声明。

不包含：

- 第二套 NestJS、TypeORM、`reflect-metadata`。
- 后端核心编译副本。
- pnpm 指向构建机的符号链接。
- 测试、游戏文件、真实页面完整副本、用户数据或凭据。
- 需要服务器执行的安装脚本。

纯抓取核心可以打包；带 Nest 装饰器的适配层使用宿主编译链，不能用缺失 decorator metadata 的快速转译替代。

### 3. 配置与版本兼容

配置采用唯一前缀，例如 `PLUGIN_GAMEVAULT_DLSITE_*`。默认启用、priority 为 20，语言为 `ja_JP`，自动匹配固定为 ID-only。

启动时校验：

- 配置类型、范围及支持语言。
- provider slug/priority 与现有来源不冲突。
- 后端版本处于明确支持的范围。
- 所需服务与匿名媒体存储契约可用。

配置错误应显式失败或禁用插件并明确报警，不静默采用意外值。priority 冲突不能通过随机挑选数字解决。

首发只宣称已验证的 17.0.1 基线；同为“v17”不自动等同兼容。宿主 `provider_priority` 储存在作品 metadata 记录上，也不能未经验证就宣传为完全独立的“每游戏个人覆盖”。

### 4. 部署与升级要求

未来部署默认：

- 游戏卷 `/files` 只读。
- `/plugins` 可由只读发布目录挂载。
- 数据库、媒体、日志、配置卷按宿主需要可写。
- 不要求容器根文件系统整体只读，因为当前插件加载器需要写入 `dist/src/modules`。
- 核验非 root 运行权限；当前 `entrypoint.sh` 在 root 模式下会尝试递归调整卷权限，不能让这一行为改动游戏存储。
- 安装为解压后的单个插件目录，不直接放 zip。

升级前备份数据库、媒体及配置；替换完整插件目录，不能混放新旧入口。升级后使用干净实例或重新创建容器。

**加载器是复制而不是镜像同步。** 删除 `/plugins/dlsite` 或某个旧 JS，并不保证已注入的旧文件消失；升级、回滚和卸载流程必须处理这一点，不能只写“重启即可”。

卸载默认保留数据库及媒体，不自动执行破坏性清理。若需要解除映射，应在插件仍注册时按原生流程进行；用户元数据必须保留。未注册来源、effective metadata 和残留媒体的后续行为要有实际记录。

## 十、测试分层与发布验收

所有执行均属于实施阶段。本计划阶段不运行这些测试；开发端到端环境不得挂载 NAS、用户游戏库或用户凭据。

### 1. Fixture parser 单元测试

每个映射字段至少覆盖正常值、确实缺省、结构/格式错误三类情况。

重点矩阵：

- RJ/BJ/VJ/RE、六位/八位、前导零、大小写、重复 ID、冲突 ID。
- 合法 URL、移动 URL 规范化、分区跳转、不同 ID 跳转、无效 ID。
- 五种首发语言、未知语言、语言回退和不同日期格式。
- 评分 4.25 → 85、5 → 100；空评价、模板变量、越界值不得伪造评分。
- 年龄 0/15/18 与未知状态。
- 社团、发行商、人员 credits 的角色分离。
- 描述缺失、广告混入、恶意 HTML、恶意链接。
- 搜索空结果、结构变化、跨区重复、同名不同作品和非游戏作品。
- 有主图/无主图、样例图与主图区分、图片 URL 非白名单。
- 关联实体在中日韩名称及改语言时的稳定身份。

`dlsite-sample.html` 可作为当前阅读与本地验证基准；公开测试仓库优先使用最小化结构 fixture 或合成内容。**不能把 Playnite 的 MIT 许可误认为涵盖 DLsite 商品说明和图片的再分发权。**

### 2. HTTP 模拟与安全测试

通过可注入 transport、模拟时钟和 DNS 响应测试，不为生产代码增加“允许内网”的开关。

必须覆盖：

- 200、304、404、410、403、429、5xx、超时、连接中断。
- JSON 返回 HTML、JSON 结构变化、200 错误页、登录页、验证码页。
- 逐跳重定向、循环跳转、超预算及 Cookie 隔离。
- 私网/本地/保留地址、IPv6、混合 DNS 响应及 DNS rebinding。
- 超大响应、解压膨胀、假图片、超大尺寸图片。
- single-flight、缓存命中/过期、负缓存分类。
- 每次真实请求间隔不少于 1,500 ms，总并发不超过 1。
- 单作品总请求、超时和重试不超过约定预算。
- **被禁止的目标实际发出请求数为 0**，不能只断言最终返回错误。

### 3. GameVault 适配契约与数据库测试

针对真实宿主接口及隔离数据库验证：

- Nest 注入使用同一套宿主类和服务。
- 默认导出和 provider 注册正常，配置错误/重复 priority 可见。
- `MinimalGameMetadataDto` 与 `GameMetadata` 的字段类型正确。
- 四类关联数组不会被稀疏刷新意外清空。
- 数值 0、空值和空数组在保存/合并中的真实语义。
- `user_metadata` 仍最高优先级；DLsite 与低优先级来源按字段整体合并。
- 相同 ID 不产生重复 provider metadata。
- 共享同一作品的多个游戏记录、并发搜索/刷新、失败恢复的行为。
- Media 匿名入库、来源记录、不可变 ID、GC 并发与错误清理。
- 远端失败前后，已保存字段、关联、Media ID 及刷新时间保持符合预期。
- 保存中途故障与并发 remap 的宿主边界，不能用 Mock 掩盖数据库行为。

以 SQLite 为快速隔离验证，同时使用 PostgreSQL 覆盖实际 ORM、唯一约束和关联保存。未通过的数据库类型不能列入支持清单。

### 4. 真实公开页面小样本

实施获准且允许访问公开页面后，在开发环境低频验证；仍不得访问 NAS。

样本必须超过 RJ150726，覆盖：

- RJ 旧六位和新八位编号。
- VJ 的相关商业分区。
- BJ 的识别/查询与非游戏自动拒配。
- 可获得的历史 RE 或旧 URL；若已停用，验证明确的不可用处理。
- `home`、`maniax`、`soft`、`pro` 及宣称支持的其他分区。
- 多语言、无评分、可选字段缺失、不同图片结构、明确下架或不存在作品。

为每个样本记录来源、预期字段、解析输出和限制；不要因为请求成功就认为字段正确。

RJ150726 的现有样本可核对作品标题、社团 `RG07939`、主图和 `2015-03-14`。HTML 中评分仍有动态模板，**不能据此声称真实评分已验证**；必须另验 JSON。

若某类旧 ID 已无法取得有效公开页面，应写明历史 fixture 与当前不可用情况，不制造成功样本。

### 5. 隔离 GameVault 端到端验收

使用临时目录中的自制合法小型游戏包和独立数据库。真实生产形态使用构建后的发行包，不只运行 TypeScript 源码。

| 场景 | 必须确认的结果 |
|---|---|
| 冷启动 | `/api/metadata/providers` 中 DLsite 恰好注册一次，没有 CommonJS、导入、重复 Nest 或 DI 错误。 |
| ID 自动关联 | 扫描带 `[RJ…]` 的包，最终 `provider_metadata`、effective metadata 和媒体正确。 |
| 多版本 | 同 ID 不重复建作品 metadata；不同版本 ID 冲突不自动挑选。 |
| `(NC)` | 任一版本含该标记时，自动流程产生的 DLsite 网络请求为 0。 |
| 无 ID | 保持未匹配；编辑者能搜索候选并 remap，后台不采用第一条。 |
| 手工 remap | 改到另一作品后，刷新和重启仍使用人工选择的 ID。 |
| 字段展示 | 标题、描述、日期、年龄、评分、社团、类型、标签、链接与映射表一致。 |
| 图片 | 实际客户端显示封面/背景；重启后仍从服务器媒体读取；更新产生新 Media ID。 |
| 搜索/筛选 | 验证 metadata 标题检索、类型/标签/开发者/发行商/日期/年龄筛选，以及宿主支持的评分排序。不承诺不存在的任意字段筛选。 |
| 优先级 | 高低来源、空字段及用户编辑的结果与宿主合并规则一致。 |
| 刷新 | TTL 未过跳过；过期并重新索引会更新；同 ID remap 可刷新；失败不冒充成功。 |
| 故障恢复 | 网络中断、403/429、下架、JSON/图片失败均不抹掉已有有效数据，恢复后可再次完成更新。 |
| 批量扫描 | 至少 100 个合成游戏条目，含重复 ID、无 ID、冲突和失败条目；限速、内存、队列及请求预算符合要求。 |
| 多客户端 | 至少两个明确版本的原生客户端读取同一服务器字段和 Media ID；不要求未支持字段的界面完全相同。 |
| 升级/回滚/卸载 | 无残留入口双重加载；数据保留行为与文档一致。 |
| 游戏卷保护 | 测试前后包内容、名称及校验和不变，未发生写入。 |

### 6. 发布门槛

只有以下条件全部满足，才称为完整首发：

- 全部身份、安全、数据保护关键用例通过。
- 所有宣称支持的字段、语言、分区和数据库都有相应证据。
- 发行包在干净生产布局下通过 ESM 加载及端到端流程。
- 无低置信自动误配、无网络失败导致的有效数据丢失。
- 限速、重试、响应大小与禁止网络目标均验证实际阈值。
- 两个原生客户端确认服务器共享元数据与图片可用。
- 安装、升级、回滚、卸载、许可和已知限制文档齐全。
- 任何宿主阻塞项已解决，或明确从兼容声明中排除；不能写成“测试通过但仍可能清空数据”。

## 十二、主要风险、默认决定与真正待决项

### 1. 主要风险及处理

| 风险 | 处理原则 |
|---|---|
| 页面/JSON 接口变化 | 结构版本化、字段状态区分、契约 fixture、错误显式化；不能把解析失败当空作品。 |
| 反爬、地区或匿名访问限制 | 统一限速、冷却与保留旧数据；不引入浏览器或账号 Cookie 绕过。 |
| 旧 ID 与跨区身份不明 | 完整 ID 保真，有限路由定位，跨 ID 跳转拒配；有证据才登记别名。 |
| 同名作品误配 | 首发 ID-only 自动关联，无 ID 人工 remap。 |
| 缺字段清空关联 | 读取同 ID 旧快照，构造完整关联数组；无法确认时拒绝刷新。 |
| 图片 SSRF 与异常文件 | 插件安全传输、DNS 绑定、位图验证、大小限制；不直接调用任意 URL 下载。 |
| 宿主非事务 map、媒体 GC 竞态 | T01 提前验证；必要时要求受支持的宿主修复，不默默改核心。 |
| 插件 API 不稳定 | 锁定实际版本/commit，随兼容版本重新构建及测试。 |
| 同作品 metadata 被多个游戏共享 | 验证共享更新与 effective metadata 刷新，不把共享记录当每游戏独立副本。 |
| 年龄未知被宿主视为可访问 | 未知不写全年龄；文档说明 provider 不是完整家长控制系统，核验宿主空年龄策略。 |
| 第三方内容再分发 | 保留代码许可，限制真实商品页面及图片进入公开测试/发行包。 |

### 2. 已给出默认值，不必反复询问

原生插件、TypeScript/ESM、独立抓取层、ID-only 自动匹配、日文原文默认、priority 20、类型进 Genres/题材进 Tags、Series/Features 前缀标签、Icon 不映射、notes 默认不写、游戏卷只读、不用账号或浏览器、不 fork 核心。

### 3. 真正待决，但不阻塞当前规划的问题

1. **实际部署基线。** 未来授权部署时，才确认 NAS 的后端精确版本、镜像、架构、数据库与客户端版本；现在不探测，首发先以本地 17.0.1 为开发基线。
2. **宿主关键接口缺口的处理。** 若 T01 证明当前版本无法保证必要的数据或媒体安全，默认等待上游受支持修复/升级兼容基线，不自动转为核心 fork。是否接受有明确边界的降级发行，需要单独决定。
3. **未来是否扩展无 ID 自动匹配。** 首发不需要该决定；只有明确要求后，才另行设计标注数据集、置信阈值、误配率验收与开关，不能在实施中悄悄打开。
